## Material render-state / composition frontier — ACTIVE

New 2026-09-23 work is now regenerating exact material render-state censuses for:

- 99 common materials;
- 74 sky materials;
- 497 light materials.

The destination-neutral decoder now preserves the complete four-byte material state
window at +0x20 for every material.

Already source-closed:
- +0x20 == 0 belongs to the opaque/no-material-blend-override population;
- +0x20 != 0 belongs to the D1 transparent draw population;
- low byte `0x88` selects exact blend-state index 8;
- blend-state 8 equation:
  `Source + Destination*(1-SourceAlpha)`.

All other nonzero blend selectors remain unresolved until independently closed.

Pinned Tiger PipelineState source correlates the four bytes in this order:

1. blend state;
2. depth-stencil state;
3. rasterizer state;
4. depth-bias state.

For lanes 1–3 this is currently **SOURCE_CORRELATED_ONLY**. It is not yet promoted
as global D1 behavior. Their raw bytes and mechanical high-bit/low-7 selected indices
are now being censused across common/sky/light so the highest-impact D1 behavioral
fixtures can be attacked next.

New tooling:

- `tools/d1_tower_material_state4_source_correlation.py`;

## What “shader closed” does NOT mean

Even with terminal equations closed for 65 common + 32 light + 43 sky families,
pixel-perfect Tower rendering is not yet proven.

Major remaining renderer gates:

1. **material pipeline composition**
   - unresolved non-0x88 blend-state equations;
   - D1 behavioral promotion of depth-stencil/rasterizer/depth-bias lanes;
   - exact selected state tables for the Tower populations;

2. **live View / Frame values**
   - retail writers;
   - backing allocations/descriptors;
   - captured values and field-level semantics;

3. **pass ordering / framebuffer ownership**
   - destination contents at each transparent/additive/attenuation pass;
   - depth/stencil ordering and inter-pass dependencies;

4. **environment renderer**
   - reflection/cubemap selection and filtering;
   - fog/atmosphere;
   - post-processing / exposure / tone mapping where applicable;

5. **runtime selection**
   - active sky collection / sky record;
   - active actor scenario / D912 group / location alternative;
   - live animation/event states;

6. **actors / dynamic VFX**
   - broad actor assets and animation options are recovered, but the entire actor/VFX
     renderer is not yet at the same 100%-terminal-equation closure as common/light/sky.

## Practical interpretation

The September 20 statement that Tower renderer work was mainly “55–70% native
material/shader reproduction” is obsolete for the three bounded static/environment
pixel-shader domains. Their terminal behavior is now closed.

A better current description is:

- **world/asset reconstruction:** very high;
- **common/light/sky terminal PS arithmetic:** source-closed for the bounded corpora;
- **pipeline composition and live renderer state:** the principal remaining static
  visual gap;
- **dynamic runtime selection / actors / VFX / post:** still material gaps to a
  pixel-perfect game-frame reconstruction.

Do not convert the 100% terminal-equation counts into a “100% Tower” claim. The
remaining layers can still materially change the final framebuffer.
